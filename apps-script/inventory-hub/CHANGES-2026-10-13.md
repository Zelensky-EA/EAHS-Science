## Install (about 10 minutes)

1. In the Apps Script editor, **Deploy → Manage deployments**. Note the current version number (this is your rollback point).
2. For each "Replace" file above: open it in the editor, select all, paste the new contents, save.
3. Choose **runSetup** in the function menu and click **Run** once. It should return "Inventory tabs and headers verified."
4. **Deploy → Manage deployments → ✏️ Edit → Version: New version → Deploy.** (Edit the existing deployment so the /exec link stays the same. Do not create a new deployment.)
5. Run through the checklist below.

**Rollback:** Manage deployments → Edit → pick the previous version number → Deploy.

## Test checklist after deploying

- [ ] Inventory page loads; Equipment catalog tab still lists the catalog.
- [ ] Add stock to one item; the new total and message appear; the catalog tab still works afterward.
- [ ] Check out and return one item.
- [ ] Type in the By room search box — results update after a short pause.
- [ ] Scan or type a barcode you have used before — it matches the saved item.
- [ ] Hub home page loads; Minutes page shows summaries; "Refresh summary" on a meeting works.
- [ ] Apps Script → Executions: `getData` no longer appears every 45 seconds per open page.

## What changed

### Fixes that stop saves from failing ("Inventory is busy")
- **Hub.gs – `refreshMeetingSummaries`**: no longer holds the shared lock while opening minutes Docs. It checks each Doc's Drive "last edited" time and skips Docs that haven't changed. It locks only for the short Sheet write, and returns only meetings instead of every hub tab.
  - *Behavior change:* automatic refresh now covers only **Upcoming** and **Draft minutes** meetings (5 most recent). Approved/older meetings still refresh with their **Refresh summary** button.
- **Barcode.gs – UPC and book lookups**: the shared lock is held only to reserve a lookup slot (same rate limits as before), never during the web request.

### Speed (server)
- **Code.gs – `locked_`**: writes are flushed and the lock is released *before* the page data is reloaded, so other teachers wait less. Saves no longer run the full 9-tab header check (page loads still check every 6 hours; `runSetup()` checks on demand).
- **Code.gs – data split**: saves return only the data that changes. The catalog and price catalog are sent once, when the page opens.
- **Code.gs – name matching**: cleaned item names are remembered within a request, and the catalog is read once and indexed. Same results (verified on 3,960 name/type/unit combinations against the original logic); about 9× faster in testing.
- **Code.gs – `rows_`, `sheet_`**: each tab and the time zone are looked up once per request.
- **Code.gs – PriceJobs**: finished ("Done") price jobs older than 30 days are no longer sent to browsers. They remain in the Sheet.
- **Barcode.gs**: barcode lookup and save read only the Items tab instead of the full inventory.
- **Hub.gs**: hub tab/header check runs at most every 6 hours (`runHubSetup()` on demand).

### Speed (browser)
- **Index.html / HubIndex.html**: data starts loading at the same time as the page code (one fewer round trip before anything appears).
- **InventoryClient.html**
  - Background refresh: price tabs only (`getPricingUpdates`), every 3 minutes, and only while a supplier lookup is Queued/Running/Retry. Previously it reloaded the full inventory every 45 s on every open page.
    - *Behavior change:* if someone else queues a lookup, your page shows it after your next save or page reload, not within 45 s.
  - Cleaned names remembered, and price lookups indexed — fewer recalculations on every redraw (same prices, verified).
  - Search redraws 150 ms after typing pauses instead of on every keystroke.
  - Built-in copies of the price catalog removed (~60–70 KB per load). The server already sends it. These copies were only used by the offline demo, which the deployed page never runs.
- **HubClient.html**: background summary check every 5 minutes instead of 90 seconds (each check is now cheap).

## Not changed (noted for later)

- Barcode `item.barcode` check: Items has no barcode column; saved links live in Script Properties.
- Lab reservation backend (all-day events marking only Period 1).
